# 思路卡输出规格 v1

> 时间：2026-10-26 19:35
> 前提：用户已确认产品边界——**只输出关键词/大纲，由本人用自己的语言组织**。不做语音代答、不给可直接朗读的成稿。
> 本文档是这个产品的核心规格：它决定了输出到底"有用"还是"像作弊"或"像废纸"。

---

## 一、为什么"给要点"比"给答案"难做

给成稿很简单：让模型像写作文一样写完就完事，用户照着念。
给要点难在**分寸**：

- 太详细 → 变成成稿，用户会照着念，产品性质变了
- 太简略 → "注意沟通" "突出成果" 这种四字空话，等于没说
- 太通用 → 不锚定他的履历，任何候选人都能用，没有价值

所以规格的第一原则是：**每一条要点都必须能直接演展开成一句人话，但它本身不是一句人话。**

---

## 二、输出结构：三段式

```
┌─────────────────────────────────────────┐
│ ① 锚点（1 行）                           │  他简历里的哪个项目/经历该被调用
├─────────────────────────────────────────┤
│ ② 要点（2–4 条，每条 ≤ 18 字）           │  关键词式，不是句子
├─────────────────────────────────────────┤
│ ③ 提醒（0–1 条，可选）                   │  容易踩的坑 / 可以反问对方的一句
└─────────────────────────────────────────┘
```

### ① 锚点

固定格式：`【锚点】万金天宇 · ERP 库存成本异常`

它同时承担三个功能：
1. **治幻觉**——模型必须先选简历里真实存在的条目，再基于它说话
2. **治空话**——用户看到锚点就知道"哦，他要我拿这个项目举例"
3. **治跑题**——如果对方问的东西简历里真没有，锚点会显示"无直接对应"，这本身是有效信息

### ② 要点

硬约束（写进 prompt，也写进校验器）：

| 约束 | 阈值 | 理由 |
|---|---|---|
| 单条字数 | **≤ 18 个汉字** | 超过就变成句子，用户会照读 |
| 条数 | **2–4 条** | 少于 2 条不够撑；多于 4 条看不过来 |
| 句式 | **禁止完整主谓宾**，优先名词短语 | 名词短语逼他自己接动词 |
| 人称 | 禁止"我……"开头 | 防止直接可朗读 |
| 数字 | 只允许简历里出现过的数字 | 编造量化数据是背调杀手 |
| 时态/语气 | 不带"首先/其次/最后"这类连接词 | 那是成稿的骨架 |

### ③ 提醒

只允许三种：
- 风险提示：`别主动提"离职原因"`
- 反问机会：`可反问：团队现在几个系统在维护？`
- 数据确认：`薪资口径：18–22K 已谈定？`

不允许出现"放松""自信一点"这类情绪安慰——那是废话。

## 三、正例与反例（用真实履历）

**问题**：*"说说你处理过最棘手的一次故障。"*

### ❌ 反例（这是代答，必须拦掉）

> 我之前在淮北万金天宇的时候，遇到过一次 ERP 库存成本异常的问题。品号 89-HBTY0005-XXX 库存有 1000 件，但余额是负的 3994.58。我先用 INVQ01 查了库存明细，又用 INV102 做了成本分析，最后发现是……
>
> **问题**：这就是一篇可以照着念的稿子。用户会念。产品性质直接变成作弊工具。

### ❌ 反例二（这是空话，必须拦掉）

> 【锚点】ERP 系统
> - 突出解决问题能力
> - 强调责任心
> - 说明结果
>
> **问题**：任何候选人都能用，等于没说。

### ✅ 正例（这是目标形态）

```
【锚点】万金天宇 · ERP 负库存成本异常

· 现象：账面 1000 pcs / 余额 −3994.58
· 路径：INVQ01 流水 → INV102 成本重算
· 关键：出入库异动类型 + 暂估凭证
· 收尾：定位到单据层，不是调总数

提醒：别急着说"我改好了"，先讲怎么定位
```

**为什么这个形态成立**：用户看着这四个关键词，必须自己补主语、补动词、补因果，说出来的话是他自己的。而且顺序已经给他了（现象→路径→关键→收尾），不会临场抓瞎。

## 四、渲染规格（浮窗上长什么样）

半透明浮窗只有 260px 高，一屏能看的字有限，所以渲染必须做取舍：

| 元素 | 规格 |
|---|---|
| 锚点 | 12px，灰色，前面一个 ● 圆点 |
| 要点 | 15px，主色，行距 1.6，每条前面一个 `·` |
| 提醒 | 13px，琥珀色，前面一个 ⚠ |
| 单卡最大高度 | 4 条要点 + 1 条提醒，超出滚动 |
| 入场 | 淡入 120ms，不要滑动（滑动会晃眼） |
| 停留 | 默认 40 秒后自动降到 40% 透明度（不消失，不打断） |
| 翻页 | `↑/↓` 切上一张/下一张，保留最近 10 张 |
| 字号 | 支持 `Ctrl + +/-` 全局缩放（有人喜欢大） |

**不做**：打字机效果、逐字流式跳动、彩色高亮关键词。**面试时任何动的东西都会把视线拽走**，人眼对动态元素极其敏感。流式输出只用于调试，正式渲染等整卡到达再一次性淡入。

## 五、延迟策略：分两段交付

整卡生成要 1.2–1.8 秒，但用户在对方话音刚落时就需要"知道该怎么开口"。所以拆两段：

| 阶段 | 内容 | 目标耗时 | 作用 |
|---|---|---|---|
| 第一段 | 锚点 + 第一条要点 | ≤ 700ms | 让他先开口，避免冷场 |
| 第二段 | 其余要点 + 提醒 | ≤ 1800ms | 说话过程中补全 |

第一段用 `max_tokens` 限制 + 更短的 prompt（只喂锚点候选，不喂全文），第二段再走完整推理。两段共用一次 prefix-cache 前缀（见 `07` 文档 §2.5）。

## 六、输出协议（两端渲染保持一致）

电脑端和手机端渲染同一份数据，所以协议必须是稳定 JSON：

```ts
interface HintCard {
  id: string;
  question: string;        // 识别到的对方问题（供回看）
  anchor: {
    kind: 'experience' | 'project' | 'education' | 'skill' | 'none';
    label: string;         // "万金天宇 · ERP 负库存成本异常"
    resumeId: string;      // 指向 ResumeData 里的条目 id，可点击跳到简历
  };
  points: string[];        // 2–4 条，每条 ≤18 字
  caution?: string;        // 0–1 条
  partial?: boolean;       // true = 只有第一段，前端显示骨架态
  ts: number;
  latencyMs: { first: number; full: number };
}
```

`anchor.resumeId` 是关键设计：**它让"锚定"这件事可验证**。校验器可以直接判断这个 id 在不在用户的 `ResumeData` 里，不在就重生成。这比让模型"注意不要编造"有效得多——**用数据结构约束，而不是用祈使句约束**。

## 七、校验器（生成之后必过一道）

不完全信任模型，生成后跑这几个检查，任一失败就重生成或降级：

```ts
function validate(card: HintCard, resume: ResumeData): Result {
  // 1. 锚点必须真实存在
  if (card.anchor.kind !== 'none' && !existsInResume(card.anchor.resumeId, resume))
    return fail('ANCHOR_NOT_FOUND');

  // 2. 要点字数
  if (card.points.some(p => p.length > 18)) return fail('POINT_TOO_LONG');

  // 3. 条数
  if (card.points.length < 2 || card.points.length > 4) return fail('POINT_COUNT');

  // 4. 不是完整句（出现句末标点或"我"开头即判失败）
  if (card.points.some(p => /[。！？]$/.test(p) || p.startsWith('我')))
    return fail('LOOKS_LIKE_ANSWER');

  // 5. 数字必须能在简历原文里找到
  for (const n of extractNumbers(card.points.join('')))
    if (!resumeText(resume).includes(n)) return fail('UNVERIFIED_NUMBER');

  return ok();
}
```

第 4 条是产品的"防代答闸门"。它比任何提示词都可靠：**提示词是建议，校验器是法律。**

## 八、怎么验证它"真的有用"

写完后别急着上人，先做离线评测：

1. 录 10 个真实面试问题（从你的 BOSS 直聘聊天记录里扒，比我编的准）
2. 每个问题跑 3 次，得到 30 张卡
3. 你自己盲评，打三个分：
   - **可用性**：看着这张卡，我 3 秒内能开口吗？（1–5）
   - **组织性**：我能不能用它说出 30 秒的话？（1–5）
   - **是否泄题式成稿**：这张卡里有没有可以直接念的句子？（有 = 不合格）
4. 可用性 < 3 或出现"可直接念"的卡，回去改 prompt 与约束

这个评测不需要写代码，一小时能做完，但它决定了后面所有工程是否有意义。
