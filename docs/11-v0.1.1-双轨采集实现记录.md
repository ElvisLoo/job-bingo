## 二、为什么要麦克风轨（本次最关键的判断）

回环方案的隐藏缺陷不是「采不到声音」，而是**采得太多**：

```
你说话 → 会议软件本地混音 / 扬声器漏音 → 系统输出 → 回环采集 → ASR
                                                        ↓
                                        被当成「面试官的新问题」→ 出一张无关的卡
```

用户实际感受是：**我一边回答，浮窗一边乱刷**。这不是 bug 的偶发现象，
而是只听回环时的必然结果，同类产品里这是最常见的差评点。

解法不是加更聪明的模型，而是加一条**物理上更近的轨**：
本地说话时麦克风贴着嘴，能量必然远强于回环；对方说话时麦克风安静，回环占主导。
两路一比，判断几乎不需要模型。

### 判定规则

```
micActive   = 麦克风 > 底噪 + 9dB  或  麦克风 > −45 dBFS
micDominant = 麦克风 − 回环 > 4 dB
me          = micActive && micDominant
```

- **绝对阈值兜底**：冷启动时底噪尚未收敛，只看相对值会把真实语音判成「无信号」。
  单测里就是被这个场景打回一次，才补的绝对判据。
- **600 ms 保持窗口**：一句话内部逐字抖动不该让归属来回翻转。
- **无麦克风轨 → `unknown` → 按对方处理**：宁可多出一张卡，不能吞掉问题。

### 段归属投票的门槛为什么是 60%

| 误判方向 | 后果 | 代价 |
|---|---|---|
| them（对方） | 多一张卡 | 低，用户看得见、可忽略 |
| me（我方） | 漏一个问题 | **高，用户当场答不上** |

代价不对称，所以门槛必须偏向 them：`me` 票 ≥60% 才判 me，
`unknown` / `silence` 不计入分母（它们不含信息，不该稀释票数）。

## 三、踩到并修掉的问题

| 现象 | 根因 | 处理 |
|---|---|---|
| 回声门单测 2 项失败 | 冷启动强音抬高底噪，后续判不出 me | 增加绝对电平判据 |
| `absentFloorDb` 把真实语音判成「无信号」 | 用「低于底噪」判断无信号，冷启动时不可靠 | 改用绝对 RMS 阈值（数字静音） |
| 改完 asr 包仍不生效 | `node_modules/@job-bingo/asr` 是**硬拷贝**（`prepare-dist.js` 实体化过），不是软链 | 每次改包后重跑 `node tools/build/prepare-dist.js` |
| 采集窗口「当前判定」一直不动 | 页面在桥未就绪时就调用 `window.capture.*`，异常中断了脚本 | 已记录，见「未完成」 |
| 新启动的实例立刻退出 | 单实例锁：旧实例还在，新进程把参数转给旧实例后退出 | 验证前先结束旧进程 |

> 关于「硬拷贝」这条：它不会报错，只会让改动静默失效。写进文档，避免下次再怀疑人生。

## 四、未完成 / 已知限制

1. **采集窗口自检时桥可能未就绪**：如果 `getUserMedia` 前发生异常，
   `window.capture.onSelfTest` 注册不到，自检按钮无效。当前靠「重开窗口」绕过，
   正规做法是把桥访问全部包在 `ready()` 守卫里 —— 属健壮性改进，不影响主链路。
2. **回声门只做能量比较**，不做声道分离。极端情况（回声消除关闭 + 扬声器外放）
   仍可能把我方语音判成 them，表现为偶发多一张卡。
3. **回环采集依赖系统音频输出**：耳机直连且会议软件走独占模式时可能拿不到混音。
4. **未处理「对方用双声道 + 我方立体声泄漏」**的边界，当前只取单声道。
5. 手机端目前仍是文本上传 / 卡片显示，**不作为第二路采集**。

## 七、v0.1.2 补充：双轨判定曾经是「假生效」

安装 v0.1.1 后实测发现：麦克风轨正常收帧，但回声门始终收到「无麦克风」，
永远判不出 `me` —— 也就是**防自我触发的核心功能在真机上根本没跑起来，而且不报错**。

### 两个叠加的静默缺陷

| # | 缺陷 | 表现 | 修复 |
|---|---|---|---|
| 1 | **协议错配**：渲染层上报 RMS 标量，主进程用 `new Float32Array(0.15)` 读 | 标量转数组得到**长度 0 的空数组** → 判为无信号 | 主进程改收数字；回声门 `toRms()` 同时接受标量与数组 |
| 2 | **AnalyserNode 旁路读全 0** | 双流下旁路接不上，且不报错 | 电平直接取 AudioWorklet 帧算 RMS，少一条旁路即少一个静默失败点 |

这两个缺陷的共同点：**都不报错**。现象只是「判定一直 unknown」，
和「本来就是单轨」长得一模一样，靠读代码看不出来，只有对比真实 dB 值才能发现。

### 新增回归（149 项）

- 回声门接受 RMS 标量 / `mic=0` 不判 me / `null` 与 `undefined` 均按无麦克风处理
- 固化 `new Float32Array(0.15).length === 0` 这一事实，防止再把标量当 PCM 用

### 真机验证（安装版 0.1.2）

| 项 | 结果 |
|---|---|
| 覆盖安装 | 0.1.1 → 0.1.2 成功，`FileVersion=0.1.2` |
| 自动采集 | `frames=142 / micFrames=141 / 16000Hz`，无错误 |
| 回声门读数 | `micDb=-108.3 / loopDb=-113.3`（**能读到真实电平**，不再是 `-120`） |
| 自检出卡 | 3 段音频 → 3 张卡，要点 ≤18 字、无句号 |

> 本机为远程桌面，麦克风无真实输入（-108 dB 为数字静音），
> 故「我方说话 → 不出卡」仍由单测覆盖，未做真机演练。
