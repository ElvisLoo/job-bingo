## 一、它到底是什么（一句话）

一个**基于 TanStack Start 的 SSR 全栈 React 应用**，不是纯静态页面。核心编辑器在前端跑，但 AI 能力走自家 `/api/*` 服务端路由，所以"塞进 Electron"要解决的不是打包问题，是**怎么给它一个运行时**。


## 三、三个决定成败的发现

### 发现 1：数据层对我们极其友好（最大的好消息）

简历不是富文本乱码，是**强类型的 `ResumeData` JSON**（`src/types/resume.ts`）：

```ts
interface ResumeData {
  id, title, createdAt, updatedAt, templateId
  basic: { name, title, email, phone, location, photo, customFields, ... }
  education: Education[]
  experience: Experience[]      // company / position / date / details
  projects: Project[]           // name / role / date / description / link
  skillContent: string          // Markdown
  selfEvaluationContent: string
  publications?, certificates[], customData{}, globalSettings{}
}
```

**这一条直接决定架构**：我们的"思路锚定简历"不需要做 OCR、不需要解析 PDF、不需要注入脚本爬 DOM——**直接读这个 JSON 就够了**，而且 `experience.details` 就是项目的原始素材，正好是"锚定具体项目、治幻觉"要的东西。

导出能力也是现成的：`src/utils/export.ts` 里已有
- `exportResumeAsJson`
- `exportResumeAsMarkdown`（可直接进 prompt 的 Markdown 形态）
- `exportToPdf` / `exportToLongPagePdf` / `exportToLongPageImage`（**纯前端 html2pdf + jsPDF + html2canvas**，不依赖服务端）

### 发现 2：AI 配置层的设计跟我们重复了，可以合并

`src/config/ai-models.ts` 已支持 6 家 + 可自定义 baseUrl + 4 种协议：

```
providers: openai | gemini | deepseek | anthropic | qwen | doubao
protocols: chat-completions | responses | gemini | anthropic
字段: { provider, protocol, apiKey, model, baseUrl, supportsPdf }
存储: localStorage["ai-config-storage"]（version 2，带迁移）
```

**这意味着**：我们自己那套"自定义模型接口"不必另起一套 UI。更省事的做法是让我们的 LLM 网关对外暴露一个 **OpenAI 兼容端点**（`http://127.0.0.1:PORT/v1`），然后在它的设置里作为一家自定义 provider 指向本地网关。用户在哪儿配置都行，两边看到的是同一批模型。

客户端调用点（都是 `fetch('/api/...')`，所以必须给它服务端）：
- `POST /api/polish` 润色
- `POST /api/grammar` 语法检查
- `POST /api/models` 模型列表
- `POST /api/ai-test` 连通性测试
- `POST /api/resume-import` PDF/Markdown 导入

### 发现 3：体积分布，能裁但不能乱裁

| 目录 | 体积 | 处置 |
|---|---|---|
| `public/fonts/resume/` | **75 MB** | 必需（WOFF2 全字库，导出与预览共用，删了排版就崩） |
| `public/fonts/*.otf/.ttf` | **149 MB** | 大部分可删，但 `src/components/Document.tsx` 直接引用了 `AlibabaPuHuiTi-3-55-Regular.ttf` 和 `-85-Bold.ttf`，这两个得留 |
| `public/fonts/landing/` | 200 KB | 落地页用，我们不做落地页 → 可删 |
| `public/template-snapshots/` | 9.2 MB | 模板缩略图，可保留 |
| `src/` | 3.6 MB | 源码 |

粗算：只留 resume WOFF2 + 两个 TTF，字体可从 225 MB 压到 **~83 MB**。但这仍然意味着**安装包会到 100 MB 量级**——这是我们同时装 Electron 和它的必然代价，得让用户知道。

## 五、接入方式：三条路，我的倾向

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 内置服务进程（推荐）** | `pnpm build` → 打好的 `dist/` 随 App 分发 → Electron 用 `ELECTRON_RUN_AS_NODE` 起 `server.mjs` → `WebContentsView` 加载 `http://127.0.0.1:PORT` | **零改源码**；SSR/API/字体/导出全部原样可用；崩溃隔离；将来升版只换一个目录 | 包体 +~85 MB；启动多 1–3 s；要管端口与进程生命周期 |
| **B. SPA 化改造** | 改构建配置出纯静态包，用自定义协议加载 | 无子进程、启动快 | **要改源码**（触到许可证灰区），且 `/api/*` 全废，得自己重写网关 |
| **C. 直接嵌官网** | `WebContentsView` 加载 magicv.art | 零体积、零构建 | 数据在别人域名下 localStorage，我们读不到；联网依赖；等于蹭人家服务，最不体面 |

**倾向 A**：唯一的成本是 85 MB，换来的是"完全没动过别人的代码"这个许可证上最安全的位置，以及所有功能开箱可用。

技术上还有两个细节要在晚上验：
1. `dist/server/server.js` 能不能在 **Electron 内置 Node（v22）** 里跑起来——`sharp` 是原生模块，存在 ABI 不匹配的风险（不过 `sharp` 只在校徽代理里用，可能根本没被 require）
2. 端口冲突与单实例：需要固定端口 + 启动探活 + 失败回退

## 六、对我们产品设计的三处反推

1. **"魔方简历仅在电脑端"这个决定是对的，而且理由更强了**——它是 SSR 应用，手机端根本装不下，也没必要。手机端只需要**只读的 `Resume` 摘要**（约 2 KB）、由电脑端通过局域网同步过去，用来做"思路锚定 + 项目引用"。
2. **思路卡的"锚点"来源可以直接用 `experience[].details` 和 `projects[].description`**，不用我再给你编一套简历模型。面试时提示"你在万金天宇做过 ERP 库存成本异常定位"这种句子，可以 100% 从 JSON 里取。
3. **AI 配置统一成一个网关**。魔方简历和面试副驾共用一套模型配置，避免用户在两处各填一遍 API Key。
