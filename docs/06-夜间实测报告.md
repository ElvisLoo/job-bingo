## 五、字体裁剪清单（实测）

### 5.1 关键发现（推翻了昨晚笔记里的一个判断）

`src/utils/fonts.ts` 并不是直接用 `.otf/.ttf`，而是：

```ts
import fontManifest from "@/generated/resume-fonts.json";
// resume-fonts.json:
// "MiSans-Normal.ttf": "/fonts/resume/MiSans-Normal.07c198f1822a.woff2"
// "NotoSansSC-Regular.otf": "/fonts/resume/NotoSansSC-Regular.689db17ebf1a.woff2"
```

也就是说：**根目录那 149 MB 的 `.otf/.ttf` 是"源字体/落地页素材"，运行时真正加载的是 `public/fonts/resume/*.woff2`（75 MB，10 个文件，覆盖全部 10 个字族）。**

唯一的直接引用是 `src/components/Document.tsx` 里的两个 `<link rel="preload">`：

```
/fonts/AlibabaPuHuiTi-3-55-Regular.ttf
/fonts/AlibabaPuHuiTi-3-85-Bold.ttf
```

它们是 **preload 提示，不是渲染依赖**（真正的 `@font-face` 指向 woff2）。但为保持"零改源码 + 零 404"的最干净状态，**这两个 TTF 仍然保留**（代价 16.5 MB）。

## 七、给明天的三条硬结论

1. **方案 A 成立，且不用改一行上游代码、不用额外打包 Node。** Electron 33（内置 Node 20.18.3）实测能把 `server.mjs` 完整跑起来。唯一代价是包体（112 MB 产物 + 生产 node_modules）和 5–7 s 冷启动；那 5–7 s 必须用「启动中」骨架屏吃掉，不能让浮窗白屏。
2. **冷启动那 5–7 s 是 SSR 预热，不是磁盘 IO。** 建议 Electron 在 `app.whenReady()` 之后立刻 `spawn` 子进程（并行做窗口初始化），并在子进程 listen 成功（约 0.8 s）就开始 `loadURL`，让浏览器去等 SSR——总感知延迟可压到 5 s 左右。
3. **字体裁剪的真实收益是 132.9 MB，不是昨晚估的 142 MB**，而"两个 TTF 必须保留"的判断需要修正为"只为 preload 保留，非渲染必需"（想再省 16.5 MB 就得改 `Document.tsx`，那就破功了，不建议）。
