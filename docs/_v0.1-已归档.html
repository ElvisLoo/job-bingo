05

模块拆解

F1 · 音频采集与会议监听P0

系统声音 Loopback + 麦克风，分轨不混音；进程与音频会话双判定识别会议软件；热插拔 3 秒内自愈。

坑：蓝牙耳机切 HFP 后 Loopback 可能取不到声，需引导有线/USB 或虚拟声卡。

F2 · 实时转写P0

VAD → 流式 ASR → 双轨说话人分离（不靠声纹猜，直接用轨道区分我/对方）。中文 WER <8%，支持专名热词表与中英混说。

F3 · 大模型网关P0

OpenAI 兼容协议为基线，任意 base_url + key + model 可接；另配 Anthropic / Gemini / Ollama / llama.cpp 适配器。快模型出提示、强模型做复盘、本地模型兜底，三者分开配置。

F4 · 提示引擎P0

只在识别到「提问」时触发，避免刷屏；追问沿上一条深化而非重写；输出后置简历事实校验，命中未出现在简历里的实体就重写（治幻觉）。

F5 · 投屏模块P0

双向设计：电脑→手机（提示上第二屏，<200ms）/ 手机→电脑（H.264 硬编，1080p@30 <150ms）。局域网 WebRTC，二维码 + 6 位码配对。

F6 · 魔方简历模块P0

可插拔 ResumeProvider 接口，首家实现魔方简历。核心产出不是「改写简历」，而是JD 匹配 + 缺口清单 + 一定会被问的 5 个问题。

F7 · 会话复盘P1

语速、口头禅、未答好的问题、对方技术词云、逐句回放（默认只留摘要不留原音）、两场面试同类问题的横向对比。

F8 · 隐私中心P0

每次启动确认采集；留存策略默认「0 天，只留结构化摘要」；一键清除；采集告知模板；地区合规开关；日志零文本内容。

技术选型

层选型理由与备选
跨平台外壳Tauri 2（Rust）包体 10MB vs Electron 150MB，内存低一个量级；Tauri 2 已支持 Android/iOS，一套 React 前端两端口，避免 Kotlin + Web 双技术栈
音频采集Rust windows crate 直调 WASAPIcpal 不直接支持 loopback，必须走 COM；备选 VB-Cable 虚拟声卡（更稳但需装驱动，慎用）
屏幕采集Windows.Graphics.Capture支持窗口级采集；注意部分会议软件会设 WDA_EXCLUDEFROMCAPTURE 导致黑屏——音频路径不受影响，这是走音频不走视频的核心理由
实时传输webrtc-rs自带拥塞控制与抗丢包；备选自研 TCP + H.264
ASRSenseVoice-Small / FunASR中文与技术专名表现最好、体积可控；备选 whisper.cpp
LLMOpenAI 兼容 + 多 adapter通用性最强，用户可自定义任意模型
本地兜底模型llama.cpp（Qwen3-4B 级量化）可嵌入、无守护进程；断网不断档
存储SQLite + sqlx + SQLCipher单文件、可加密、双端一致
导出typst（PDF）+ docx-rs版式精确，能保证单页 A4 与页边距控制
07

合规分析：技术中立，用途定性质

你问的「这违不违反法律」——答案是：录音本身在多数情况下不违法，但产品化方式决定它是不是违法产品。

合法的支撑点

  • 你是对话参与方，录自己参与的对话，司法实践通常认可（《民诉法解释》第 106 条反向推论）
  • 默认全本地处理、不上传、不留原始音频 → 满足《个保法》第 6 条最小必要
  • 有可见采集指示 + 双方知情 → 有合法性基础（第 13 条）
  • Coach / Recorder 形态几乎无法律风险，且是更好的生意

风险的真实来源

  • 欺诈：《劳动合同法》第 8/26/39 条 —— AI 代答可致 offer 撤销、合同无效、在职被解除（对你当下求职最现实的风险）
  • 隐私：《民法典》第 1032/1033 条 + 第 1023 条（声音参照肖像权保护）
  • 个人信息：《个保法》第 28–29 条 —— 一旦做声纹识别即落入敏感个人信息，需单独同意
  • 传播：《治安管理处罚法》（2026-01-01 施行）散布他人隐私；面试题可能构成《反不正当竞争法》下的商业秘密
  • 平台：应用商店对「欺骗性用途」零容忍，灰色工具生命周期以周计

四条绝对红线（写进代码，不是写在文档里）

  1. 不做隐蔽采集 —— 进程名、图标、托盘指示不可伪装；采集时必有可见指示且不可关闭。
  2. 不做规避检测 —— 不 hook 会议软件、不改窗口属性、不伪造音频设备。
  3. 不做语音代答 —— 不把答案 TTS 念给用户。这一步把「辅助思考」变成「代替应答」，性质彻底改变。
  4. 不做内容外传 —— 不提供面试题一键分享/社区题库之类功能。
我的独立判断：MVP 就以 Coach（模拟训练 + 复盘）为主形态上线，Assistant 作为「知情同意 + 本地处理 + 不代答」的高级能力并只对确认过合规声明的用户开放。先把发动机造好，方向盘往合规那边打。理由不是保守：作弊工具的商业寿命由平台封禁速度决定，而你正在求职，欺诈风险对你是不可承受的。

需要你定的 6 件事

这 6 项决定架构走向，定了我就能出数据库 schema、API 契约和 M0 的代码骨架。

1
投屏方向　手机→电脑，还是电脑→手机？
我倾向先做「电脑→手机」（提示推到第二屏），这才是真需求；反向多为演示/双机位场景。
2
魔方简历的形态　第三方在线产品，还是你那套自研单页模板？
前者要设计导入/API 对接，后者可直接内嵌为数据源并复用你的字体缩放与页边距脚本。
3
主形态　Coach 为主，还是 Assistant 为主？
直接决定合规定位、商店审核口径、以及我做多少「隐身」相关功能。
4
是否要求全离线　断网必须能用吗？
若必须，本地模型 2–4GB，安装包策略改为「按需下载」，首次启动体验要重新设计。
5
是否面向境外　会卖给非中国大陆用户吗？
涉及 GDPR、美国 all-party consent 州（如加州），需要地理围栏与差异化策略。
6
商业化路径　个人订阅，还是 B 端 HR 记录？
C 端量大但合规敏感；B 端量小但干净、可开票、可签 DPA，而且就是你现在最熟的企业 IT 采购场景。
