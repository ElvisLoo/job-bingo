# 功能边界：把"隐身"拆成七件事

> 时间：2026-10-26 19:25
> 起因：用户指出"不可检测/隐身是这类软件的标配，应该实现类似功能，代码也可以借鉴"
> 结论：**用户的判断七成成立**——但成立的七成是"窗口级 UX 机制"，不成立的三成是"内容保护 + 主动对抗"。这四个机制该做，而且我一条都不会省；剩下三条我建议不做，理由不是道德，是收益结构。

---

## 一、先确认事实：它确实是标配

调研的 top 5 项目里 4 个明确以此为主卖点：

| 项目 | 隐身手段 | 说明 |
|---|---|---|
| Natively（3082★） | content protection + 无任务栏 | README 里 "stealth mode" 是特性列表第一项 |
| pluely（2755★） | "Completely undetectable in video calls, screen shares, and recordings" | Tauri，10MB |
| MeetingCopilot（364★） | `win.setContentProtection(settings.data.ui.stealth)` | 设置项里就是一个 switch |
| Aura-AI（90★） | "An undetectable AI assistant that lives on your screen" | 连名字都这么写 |

所以"是不是标配"这个问题不用讨论了，是。

但**"标配"不等于"必须"，更不等于"技术上有含量"**。下面是拆解。

---

## 二、拆成七件事：哪些我照做，哪些我不做

| # | 机制 | 用户感知 | 真实性质 | 我的取舍 |
|---|---|---|---|---|
| 1 | `alwaysOnTop(true,'screen-saver')` + `showInactive()` | 浮窗压在所有窗口之上，出现时不抢你的输入焦点 | **纯 UX**：不打断你说话 | ✅ **做，必做** |
| 2 | `skipTaskbar: true` + `setVisibleOnAllWorkspaces` | 不占任务栏、切虚拟桌面不丢 | **纯 UX**：不侵占工作区 | ✅ **做** |
| 3 | `setIgnoreMouseEvents(true,{forward:true})` | 鼠标点得穿过去，底下的会议软件照常操作 | **纯 UX**：不挡你打字 | ✅ **做，必做** |
| 4 | `transparent + frame:false + 亚克力` | 半透明浮在桌面上，不突兀 | **纯 UX**：视觉融合 | ✅ **做，必做** |
| 5 | 热键"一键收起"（`win.hide()` + 清屏） | 按一下就消失，再按一下回来 | **中性**：可以是"老板走过来"，也可以是"不想被录" | ✅ **做**，叫"收起"不叫"隐蔽" |
| 6 | `setContentProtection(true)` | 你共享自己屏幕/录屏时，这个窗口不出现在共享画面里 | **双面** | ⚠️ **做，但默认关、场景化开**（见第三节） |
| 7 | 进程名伪装、隐藏进程、hook 会议软件、清使用痕迹、自动绕开检测 | 对方查不到你在用 | **纯对抗** | ❌ **不做** |

**关键事实：1–5 才是"看起来像一个隐身工具"的真正原因。** 前五条全是 `BrowserWindow` 的构造参数和三个 API，加起来不到 30 行，本来就是 M0 的一半。它们让软件"存在感很低"，动机是**别打扰你**，不是**别被发现**。这部分我全给，而且给得比它们好。

真正的"隐身"只有第 6 条 —— 一条 API。而第 7 条才是军团级对抗，也是这些项目最容易烂尾的地方。

---

## 三、第 6 条：内容保护，技术上有一点必须讲清

```ts
win.setContentProtection(true);   // Windows → SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)
```

它**不改变画面给谁看**，只改变"本机屏幕捕获 API 能不能抓到这个窗口"。生效边界：

| 场景 | 是否有效 |
|---|---|
| **你**共享自己的屏幕给面试官 | ✅ 有效（对方看不到你的浮窗） |
| **你**本地用 OBS/录屏软件录复盘 | ✅ 有效（录像里没有浮窗） |
| 面试官共享**他**的屏幕 | ➖ 无关（浮窗在他机器上压根不存在） |
| Windows 10 低于 2004 / 部分远程控制软件 | ❌ 无效 |
| 对方要求"共享单个窗口"或远程接管你的桌面 | ⚠️ 取决于捕获方式 |

所以它同时服务两个场景，一个正当一个不那么正当：

- **正当**：复盘录制。你录下整场面试回看，浮窗上的草稿和你的简历摘要不该被录进去（否则录像一团乱，而且里面可能有你不想留存的私人信息）。密码管理器、网银控件都在用同一个 API 保护自己。
- **不那么正当**：共享屏幕给面试官时，让他看不见你在用辅助。

**我的处理**：能力实现，默认关闭，由"复盘录制"场景自动开启；文案写"防止你的草稿被录进复盘视频"，不写"对方看不见"。同时**不做**让它默认开启的"一键作弊模式"。

这不是道德洁癖，是产品口径问题：**同一个 API，命名为"内容保护"是功能，命名为"隐身模式"是承诺。** 承诺"对方发现不了"就是在法律文件里给自己写关键字。

## 四、"借鉴代码"这件事，得分开看

你说"天下文章一大抄"，对。但抄的收益分布极不均匀：

| 想抄的东西 | 抄的成本 | 抄的收益 |
|---|---|---|
| loopback 采集 / AudioWorklet PCM / VAD 分段 / ASR worker 契约 / FunASR sidecar | 高（这些是真功夫，坑很多） | **极高**：省 16–18 人日 |
| prefix-cache 预热 / safeStorage / residualEchoGate | 中 | **高**：直接影响延迟与安全 |
| `setContentProtection(true)` | **零** | **零**：一行 API，抄不抄都一样 |
| 进程伪装 / 反检测 | 高，且持续 | **负**：平台一更新就失效 |

有意思的地方在这里：**你最想抄的那一条，恰恰是唯一没有技术含量的那一条。** 一条 API，你自己写也就十秒钟。而真正值钱的那五个模块，我们已经决定要抄了。

也就是说，"要不要抄"这个问题的答案是"要"，但它跟隐身功能没关系。

## 五、为什么第 7 条我建议不做（三个成本，都不是道德）

### 成本 1：这是负和游戏，且没有终点

不可检测不是一次性功能，是**持续对抗**。会议软件每次更新捕获方式、Windows 每次改显示亲和性 API、显卡驱动每次改 DXGI 路径，你就得跟一次。Project-raven 的 README 里光 AEC 的原生依赖就有 5 步编译流程；Natively 有 72 万 KB 的仓库体积，大量是各种适配。

单人维护这种军备竞赛，结局是**功能慢慢失效 → issue 堆积 → 项目烂尾**。而音频链路、延迟优化、简历锚定这些是**可累积的资产**，做一次就一直有用。

### 成本 2：它对你的求职是净负债（这条最实际）

你现在在苏州找 18–22K 的信息化经理岗，博客 jikegang.com 和 GitHub ElvisLoo 是你的作品门面 —— 这是你自己定的策略。

一个以"面试中不被发现"为卖点的仓库，挂在你门面上会发生什么：

- **加分 ≈ 0**。HR 和技术面不会因为你"实现了隐身"觉得你强，因为这东西一行 API；反而会怀疑整套代码是抄的（你确实抄了，而且开源可查）。
- **减分是确定的**。招聘方搜到 `interview-copilot` + `undetectable` + 你的名字，第一反应不是"这人技术好"，是"这人会作弊，而且会拿作弊当作品"。**诚信问题在 HR 环节是一票否决，不问技术。**
- 你还是协商离职（N 赔偿）的背景，任何"职业操守"相关的负面信号都会被放大。

这件事跟道德无关，是资产配置：**你正在用最贵的那个标签（诚信），去换最便宜的那个功能（一行 API）。**

### 成本 3：法律定性会从"辅助"跳到"欺诈工具"

这个分界线是有明确位置的，不是模糊地带：

| 形态 | 法律性质 | 后果 |
|---|---|---|
| 给你思路要点，你自己组织语言 | 类似"小抄/笔记"，属个人准备方式 | 有争议但通常不被认定为对招聘方的欺诈 |
| 直接给你成稿答案，你照着念 | 对招聘方的虚假陈述 | 《劳动合同法》8/26/39 条：offer 可撤销、合同可主张无效、在职可被解除 |
| 主动隐藏、对抗检测、让你"绝不会被发现" | **证明主观故意** | 前者还能说"我不知道有风险"，这一条把"明知"钉死了 |

第三条最阴的地方：**它不改变你的行为，只改变举证。** 一个默认开启隐身的工具，在任何争议里都是"当事人明知并刻意规避"的证据。而这正是这些竞品全部踩在坑里的地方 —— 它们不是不懂法，是它们的用户不需要考虑后果（一次性用，用完就走）。你不一样，你是在做作品集。

## 六、所以我实际会做的（可执行清单）

**M0 就已实现，一条不少：**

```ts
const overlay = new BrowserWindow({
  width: 720, height: 260,
  frame: false, transparent: true, hasShadow: false,
  resizable: true, movable: true,
  skipTaskbar: true,          // ② 不占任务栏
  focusable: false,           // ① 永不抢焦点
  alwaysOnTop: true,
  backgroundColor: '#00000000',
  webPreferences: { preload, sandbox: true },
});
overlay.setAlwaysOnTop(true, 'screen-saver');       // ① 压住全屏会议软件
overlay.setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true });
overlay.setIgnoreMouseEvents(true, { forward: true }); // ③ 点击穿透
overlay.showInactive();                                  // ① 出现但不抢焦点

// 鼠标悬停时才允许交互（穿透 ↔ 可点 的动态切换）
overlay.on('blur', () => overlay.setIgnoreMouseEvents(true, { forward: true }));

// ⑥ 内容保护：默认关，只在复盘录制时开
ipcMain.handle('overlay:setContentProtection', (_e, on: boolean) => {
  if (process.platform === 'win32') overlay.setContentProtection(on);
});
```

加一个托盘图标（右键菜单：显示/收起/开始录制复盘/退出），以及热键 `Ctrl+Alt+H` 收起。

**明确不实现的四项**（会写进 README 的"设计边界"里，作为产品立场而不是免责声明）：
1. 语音代答（TTS 替你说话）
2. 伪装进程名 / 从任务管理器隐藏 / 改图标冒充系统进程
3. hook、注入或干扰任何会议软件
4. 自动清除使用痕迹

## 七、一句话总结

**能力上我可以做到和它们一样"看不见"，但我不打算把"看不见"当成卖点。**

你做的是给人用的工具，它们做的是给一次性作弊用的商品。前者的护城河是"我懂这个人的处境"，后者的护城河只有"暂时没被封"。抄它们的音频链路（值 16 人日），别抄它们的定位（值 0，还倒欠）。

---

## 附：如果最终决定默认开启内容保护

我会照做，但会同时做三件事，缺一不可：
1. README 与产品内首启提示里明确写"本工具会向面试官隐藏浮窗，是否使用由你自行判断并承担后果"
2. 首次开启时弹一次不可跳过的说明，记录到本地审计日志
3. 不在任何页面出现"对方发现不了""绝不被检测"这类宣称

这样至少在法律上你是"提供了工具并明示风险"，而不是"承诺帮你作弊"。这两者在举证时的差别，比功能本身大得多。

## 八、当前锁定值（未拍板项按推荐执行，随时可改）

用户未就以下两项做选择，为避免阻塞 M0，按推荐值实施，并保留一行配置开关：

| 待定项 | 当前取值 | 改动成本 |
|---|---|---|
| 内容保护默认状态 | **默认关**；进入"复盘录制"模式自动开 | 一个 `settings.json` 默认值，改一行 |
| 第 7 类反检测 | **不实现** | 若要加，需新增进程层代码，约 1–2 人日 |

配置项设计（写进 `packages/core/config.ts`）：

```ts
interface VisibilityConfig {
  contentTypeProtection: 'off' | 'review-only' | 'always';  // 默认 'review-only'
  hideFromTaskbar: boolean;        // 默认 true
  hotkeyCollapse: string | null;   // 默认 'CommandOrControl+Alt+H'
  adversarialStealth: false;       // 类型层面写死 false，要开需改代码
}
```

最后一项用**字面量类型 `false`**而不是 `boolean`，是故意的：改它必须改代码、走一次 review、在 changelog 里留痕。让它"可配置"就等于让它"默认会被打开"。
